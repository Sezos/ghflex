# ghflex Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `ghflex`, an npm CLI that turns anyone's GitHub into a story-sized terminal card with an AI meter. Running it is just `npx ghflex`.

**Architecture:** The tool has four layers:
1. **Pure data math:** stats, the AI signature classifier, the meter.
2. **A renderer** that turns card data into width-checked `Line` arrays (styled spans).
3. **Two outputs** that read those arrays: ANSI for the terminal, SVG→PNG for `--story`.
4. **A thin GitHub GraphQL layer and CLI shell,** with dependencies injected so everything can be tested without the network.

**Tech Stack:** TypeScript (ESM), Node ≥ 22, vitest, Biome. The only runtime dependency is `@resvg/resvg-js`, which ships prebuilt binaries. HTTP uses Node's built-in `fetch`.

**Spec:** `docs/superpowers/specs/2026-11-11-ghflex-design.md`. The prototype is `docs/superpowers/specs/prototype-gitflex.py`, and the approved mockups are in `docs/superpowers/specs/mockups/`. Read the spec before starting. The prototype is the visual reference for every section the spec says to "port".

## Global Constraints

- Package `ghflex`, binary `ghflex`, MIT license, repo `Sezos/ghflex`. `"engines": { "node": ">=22" }`, `"type": "module"`.
- Card content width: **every line ≤ 56 visible columns**. 256-color ANSI only. No emoji anywhere in the card (they break column alignment).
- The only runtime dependency is `@resvg/resvg-js`. Load it with a dynamic `import()` only when `--story` is used.
- Network calls go only to `https://api.github.com/graphql`. No telemetry. Send the header `User-Agent: ghflex`.
- The token never appears in output, errors or logs. The saved token lives at `$XDG_CONFIG_HOME/ghflex/token` (default `~/.config/ghflex/token`; on Windows `%APPDATA%\ghflex\token`) with mode `0600`.
- AI meter rules:
  - window is **90 days**, on default branches
  - count **commits, not lines**
  - **exclude merge commits** (more than one parent)
  - scan at most **60 repos**
- Peek mode (any positional username) never shows private repos or private repo data.
- The card footer always shows `npx ghflex`. There is no flag to remove it.
- The `--story` PNG is exactly **1080×1920**.
- Target: the card appears in ≤ 10 s for a typical account.
- Exact copy from the spec:
  - Pitch: `Your whole GitHub in one screenshot. Stats, stack, streak, and how much of it AI wrote.`
  - AI prompt: `Set up ghflex for me: https://github.com/Sezos/ghflex/blob/main/AGENTS.md`
  - Footnote: `AI = commits signed by an AI co-author/agent, last 90d`

## Review Focus

These are inputs the spec implies but doesn't spell out. Each line has a test in the task that owns it.

1. **Org repos behind SAML SSO, or otherwise forbidden.** GraphQL returns `null` for the repo plus a `FORBIDDEN` error. Skip that repo quietly; the card still renders. (Tasks 9, 11)
2. **Human co-authors whose names look like AI tools,** such as "Claude Dupont", "Devin Smith" or "Jules Martin", must count as **you**, not AI. (Task 3)
3. **Peeking at an org login or a username that doesn't exist.** Print `No GitHub user named '<login>'.` and exit 1, with no stack trace. (Tasks 10, 13)
4. **Output piped to a file, or `NO_COLOR` set.** Write no escape codes, don't clear the screen, don't animate. (Task 8)
5. **Ctrl-C while loading or while the card is revealing.** Show the cursor again, clear the spinner line, and exit with code 130. (Task 8)

### Task 3: AI signature classifier

**Files:**
- Create: `src/ai/signatures.json`, `src/ai/classify.ts`
- Test: `tests/ai/classify.test.ts`

**Interfaces:**
- Consumes: `Bucket`, `CommitRecord` (Task 1)
- Produces:
  ```ts
  export interface Classification { bucket: Bucket; aiName: string | null }
  export function classifyCommit(c: Pick<CommitRecord, 'message' | 'authorName' | 'authorEmail' | 'authorLogin'>): Classification;
  export function isAgentAuthor(a: { authorName: string; authorEmail: string; authorLogin: string | null }): boolean;
  ```

**Data file shape.** This is the one file contributors edit to add a tool. **Match co-authors by email only, never by name**, to protect human co-authors.

```json
{
  "coauthorEmails": [
    { "tool": "Claude",  "pattern": "noreply@anthropic\\.com$" },
    { "tool": "Cursor",  "pattern": "^cursoragent@cursor\\.com$" },
    { "tool": "Copilot", "pattern": "\\+copilot@users\\.noreply\\.github\\.com$" },
    { "tool": "Aider",   "pattern": "@aider\\.chat$" }
  ],
  "messageMarkers":    [ { "tool": "Claude Code", "pattern": "Generated with \\[?Claude Code" },
                         { "tool": "aider", "pattern": "^aider: " } ],
  "authorNameMarkers": [ { "tool": "aider", "pattern": "\\(aider\\)$" } ],
  "agentAuthors": [ "copilot-swe-agent", "devin-ai-integration", "google-labs-jules",
                    "claude[bot]", "chatgpt-codex-connector", "cursor[bot]" ]
}
```

All patterns are case-insensitive regexes. `agentAuthors` entries are plain case-insensitive substrings matched against the author name, email and login, not regexes.

Before shipping, add any other tools (Codex, Gemini, Windsurf, Devin trailers) **only if** you can confirm their exact trailer email from official docs or a real public commit. Leave out anything you can't confirm.

**Behavior:**
